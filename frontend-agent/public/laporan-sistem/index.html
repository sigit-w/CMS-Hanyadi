Kelola konten

Admin membuat TO lewat satu form: nama, tanggal pelaksanaan, mapel, daftar soal pada mapel tersebut, dan peserta dari tabel tryout_participants. Opsi “Jadikan sesi aktif” menonaktifkan sesi lain; daftar TO menampilkan jumlah soal, peserta, dan submission.

Kelola Peserta

Menu #/tryouts/peserta membuat, mengubah nama/email, menonaktifkan, dan mereset password peserta. Password saat pendaftaran otomatis terisi nama depan@mmyy dan bisa diganti. Peserta login memakai email; admin bisa mencabut sesi saat reset password. Role peserta tidak tersedia lagi di Buat User.

Kelola akses

Buat user, ubah password, assign/revoke role, centang 14 permission dengan tombol pilih semua/kosongkan/simpan.

Grup API (OpenAPI 0.3.0)

/api/v1/auth/* · roles/permissions/users · participants (CRUD + reset password) · mapels (CRUD + include_inactive)/questions (detail + PUT konten lengkap)/import/sources · uploads/{filename} · tryouts (create/list/detail/delete) · tryout/questions · tryout-sessions · reports/tryout · presentation/questions/{id} (tabel inti; /variants deprecated/404), /submit, attempts/summary. Submit dan summary peserta tidak mengirim kunci (correct_key/correct_keys), status benar/salah, atau skor. Middleware server-side: tanpa sesi → 401, tanpa izin → 403; admin terakhir tidak bisa kehilangan role admin.

Slide 16 · Replikasi

Prinsip Anti-OOM untuk Replikasi

Pemisahan sesi

Satu sesi OpenCode baru per fase. Satu fokus per prompt. Selesaikan satu fase sebelum membuka fase berikutnya.

Ruang lingkup sempit

Minta agen membaca satu direktori per langkah. Jangan minta ringkasan seluruh repository, node_modules, atau dump besar sekaligus.

Output dibatasi

Minta ringkasan maksimal 100 baris dan simpan ke docs/replikasi/fase-XX.md. Jangan mencetak isi .env, kunci, atau sertifikat privat.

Satu proses berat pada satu waktu

npm ci → npm run build → restart service, berurutan. Tetapkan NODE_OPTIONS dan MemoryMax persis seperti produksi.

Landasan: server hanya 1,9 GiB RAM. Menjalankan dua build Node atau dump database bersamaan sangat mudah memicu OOM.

Slide 28 · Perubahan Terbaru

Detail/Edit Soal, Subdomain & Privasi Penilaian

Editor pertanyaan

Field Pertanyaan memuat teks dan unggah gambar PNG/JPEG/WebP/GIF maks 5 MB dengan pratinjau. Teks boleh kosong bila gambar diunggah; backend memakai penanda [Gambar soal] agar tetap memenuhi constraint database. Tipe multi-jawaban memakai checkbox dengan minimal satu kunci benar yang disimpan di correct_keys.

Hapus soal

Tombol Hapus di halaman Daftar Soal tersedia untuk questions.write (admin/editor) dengan konfirmasi. DELETE /questions/{id} mengarsipkan soal; daftar aktif menyembunyikannya dan filter status=archived menampilkannya kembali.

Detail & edit soal

Klik baris di Daftar Soal membuka modal detail dari GET /questions/{id}. Tombol Edit soal mengubah stem, gambar, mapel, tipe, kesulitan, opsi, kunci, jawaban teks, dan pembahasan. PUT /questions/{id} menerima JSON atau multipart dan memperbarui tabel inti, opsi, serta kunci dalam satu transaksi.

Subdomain

crm. dan office. tidak menjalankan aplikasi; keduanya mengikuti vhost root di HTTP dan HTTPS. Static CMS dihapus dari layanan 8082, sehingga api. tidak menduplikasi dashboard cms.; health dan proxy presentation tetap berfungsi.

Penyimpanan gambar

POST dan PUT /questions menerima JSON atau multipart payload + image. File disimpan di UPLOAD_DIR dan dilayani publik sebagai /api/v1/uploads/<filename>; gambar lama dihapus saat diganti.

Model data

Migrasi 007–009 menambah gambar soal, sesi/relasi TO, dan tryouts.manage. Migrasi 010 menambah tryout_participants, memindahkan submission/sesi/junction ke participant_id, serta menonaktifkan role peserta. Migrasi 011 menambah kelas (int) dan sekolah pada peserta. Migrasi 012 mengganti tabel categories menjadi mapels, kolom category_id menjadi mapel_id, serta alias view menjadi mapel_code/mapel_name. Migrasi 013 melonggarkan kode mapel menjadi format unik 2–32 karakter dan menambah permission mapels.manage. Migrasi 014 menambah kolom correct_keys pada varian, mengisi dari correct_key lama, dan memperluas CHECK tipe soal dengan multiple_answer. Migrasi 015 menyederhanakan status menjadi approved (tanpa draft/review) sesuai ADR-004.

Privasi peserta

/presentation/questions/{id} (tabel inti), /submit, dan attempts/summary tidak mengirim kunci (correct_key/correct_keys), status benar/salah, atau skor. Endpoint /variants deprecated/404 sejak Fase 6j. Penilaian tetap dihitung di server untuk kebutuhan laporan admin.

Laporan tryout

Menu #/reports/tryout mengelompokkan hasil per sesi (nama + tanggal), peserta (nama, kelas, sekolah), dan mapel; menampilkan jumlah benar, salah, dan skor. Detail perbandingan jawaban tidak ditampilkan di UI.

Alur Manajemen Tryout

Admin mengisi nama tryout, jadwal mulai/selesai, mapel, dan lembar soal. Peserta opsional: A. Peserta Didik memilih siswa aktif, B. Peserta Umum membuat Nama/Sekolah/PIN/WA. Setelah tryout tersimpan, tombol Kelola Peserta membuka daftar peserta plus dua tombol A/B yang sama; penambahan langsung tersimpan lewat POST /tryouts/{id}/participants.

Sesi & akses
